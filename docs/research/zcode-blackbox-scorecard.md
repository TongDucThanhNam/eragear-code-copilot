# ZCode Black-Box Scorecard

Date: 2026-06-11

Scope: product-workflow comparison only. ZCode was launched as an end-user app
from `C:\Program Files\ZCode\ZCode.exe`. Observation was limited to visible app
behavior, window/process tree shape, child commands, listener state, and
screenshots. No ZCode archives, binaries, app package contents, private assets,
secrets, tokens, or private config contents were opened, copied, or unpacked.

Status: Eragear is at partial ADE parity. Core Electron flows now pass, but the
app is not yet full ZCode parity because several hardening and UX depth areas
remain.

## Black-Box Observation

- ZCode opened a native Electron desktop window titled `ZCode`.
- The latest observed process tree had 9 new ZCode-owned processes: Electron
  main, renderers, GPU, crashpad, network service, Node service, and ACP child.
- The Node service spawned a visible ACP child command for the current
  workspace: `zcode-acp-glm-eragear-code-copilot acp`.
- No ZCode-owned local `Listen` TCP socket was observed in the launch sample.
- The ZCode processes started for the sample were closed after observation.

## Comparison Note

ZCode's black-box launch confirms a serious Electron ADE shape: native window,
local runtime delegation, ACP child process, and visible workspace flow. Eragear
now exercises the same core local-ADE categories with its own implementation:
private Electron IPC transport, OpenCode and Codex doctor-backed provider readiness probes, MCP protocol
discovery plus panel and `/mcp` chat manual tool/resource invocation with redacted persisted audit,
bounded SSE discovery reconnect/replay plus safe SSE resource invocation
reconnect/replay and side-effecting tool no-replay policy,
trusted project-local MCP injection into ACP session setup plus stdio broker enforcement/audit and redacted Agent Session Routing preview,
fingerprint trust gating, and redacted MCP notification history,
checkpoint safety restore,
memory/capability actions, local slash command invocation, manual skill invocation,
output-style invocation, manual
subagent invocation, trusted env-scoped manual plus explicit lifecycle hook
execution across project/checkpoint and agent session events,
trusted env-scoped project-local plugin execution, metadata plus code-symbol/task indexing,
manual `/index` retrieval into chat, source-selective server-built `/memory` project context plus chat source picker,
automatic metadata-based Project Index plus Project Memory context for normal prompts,
redacted ACP Activity plus redacted trace export/replay and
correlation summaries in the Electron control surface, a workflow-readiness
first screen with live Active Workspace focus plus real Next Actions routing,
and a verified agent session loop. Further hardening is now
concentrated in execution, memory, and debug depth: richer hook confirmation and
audit review policy, signed plugin install/distribution policy, broader plugin
permission model and stronger sandbox, richer remote MCP notification delivery
across reconnects, deeper native HTTP/SSE MCP policy/audit after session injection, deeper ACP replay causality tooling, richer checkpoint
merge/conflict resolution for overlapping edits, semantic/embedding retrieval,
and broader remote administration policy.
